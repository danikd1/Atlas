# SberAgency Crawler

Пайплайн для сбора, фильтрации и суммаризации статей с Habr.

## Возможности

- 📥 Сбор статей из RSS-лент Habr
- 🔍 Фильтрация по ключевым словам с лемматизацией (таксономия D/GA/A)
- 🎯 Фильтрация по эмбеддингам (topic embedding из описаний топиков в таксономии)
- 📄 Извлечение полного текста статей
- 📝 Суммаризация статей с помощью LLM (GigaChat)

## Установка

1. Клонируйте репозиторий (или используйте существующий проект)

2. Установите зависимости:
```bash
pip3 install -r requirements.txt
```

3. Настройте таксономию и выбор узлов: ключевые слова и описания топиков задаются в `data/taxonomy.json` (узлы D/GA/A); выбранные узлы для пайплайна — в `config.config.TAXONOMY_SELECTION`.

## Использование

### Запуск пайплайна из командной строки

По умолчанию используются узлы таксономии из `config.config.TAXONOMY_SELECTION`:

```bash
python3 -m src.main
```

**Запрос через агента-роутера (LangGraph + GigaChat):** если передать `--query`, агент по запросу на естественном языке выберет узлы D/GA/A, и пайплайн запустится с этой выборкой:

```bash
python3 main.py --query "как определить границы MVP"
```

При необходимости уточнения агент вернёт вопрос; при `status=not_found` пайплайн запустится с `TAXONOMY_SELECTION` из config.

**Только тест роутера (без пайплайна):** посмотреть, как агент определяет узлы и почему он выбрал именно их:

```bash
python3 main.py --router-only --query "как определить границы MVP"
```

Или напрямую модуль роутера:

```bash
python3 -m src.agents.router "как определить границы MVP"
```

В выводе: выбранные D/GA/A, уверенность (confidence), нужное ли уточнение и поле **«Почему выбран этот узел»** (reasoning от LLM).

Результаты сохраняются в `outputs/articles_filtered.csv`.

### Веб-интерфейс

Запуск интуитивного веб-интерфейса (FastAPI + статическая вёрстка):

```bash
uvicorn src.api.app:app --reload --host 0.0.0.0 --port 8000
```

Откройте в браузере: **http://localhost:8000**

В интерфейсе доступны:

- **Подбор темы по запросу** — ввод запроса на естественном языке, получение узлов таксономии (D/GA/A) и обоснования.
- **Запуск пайплайна** — сбор из RSS, фильтрация и сохранение в коллекцию (можно использовать выборку роутера или задать имя коллекции).
- **Коллекции** — список сохранённых коллекций с метаданными.
- **Вопрос по коллекции** — RAG + LLM: вопрос по статьям выбранной коллекции и ответ с источниками.
- **Дайджест по коллекции** — формирование дайджеста по разделам (тренды, методы, инструменты, кейсы).

## Состав директорий

- **`frontend/`**: клиентская часть (SPA без сборщика) — страницы, стили и логика UI для работы с коллекциями, Q&A и дайджестом.
- **`src/`**: серверная и вычислительная логика проекта (API, пайплайн, RAG, агенты).
  - **`src/api/`**: HTTP API (FastAPI) — эндпоинты для роутера, пайплайна, коллекций, Q&A и дайджестов.
  - **`src/agents/`**: LangGraph-агенты — роутер темы (D/GA/A) и Q&A-агент для ответов по коллекции.
  - **`src/qa/`**: модуль Q&A — retrieval, rerank и сборка ответа на базе RAG + LLM.
  - **`src/digest/`**: модуль дайджестов — загрузка чанков, кластеризация/разделы и сборка итогового дайджеста по коллекции.
  - **`src/tools/`**: инфраструктурные утилиты — PostgreSQL (схема/операции), LLM, извлечение текста, загрузка промптов, rate limiting.
  - **`src/core/`**: общие константы и базовые типы, используемые в нескольких модулях.
- **`config/`**: конфигурация приложения — RSS-источники, параметры пайплайна, RAG и подключения к БД/LLM.
- **`data/`**: доменные данные и промпты.
  - **`data/taxonomy.json`**: таксономия D/GA/A и ключевые слова/описания топиков.
  - **`data/prompts.json`** и **`data/prompts/`**: шаблоны промптов для LLM (суммаризация, фильтры).
- **`docs/`**: документация по архитектуре и развитию проекта.
- **`tests/`**: автотесты (pytest) для основных модулей.
- **`outputs/`**: выходные файлы и артефакты прогонов/тестов (CSV и т.п.).

## Описание структуры клиентской части

Клиентская часть — одностраничное веб‑приложение в каталоге `frontend/` (HTML + CSS + нативный JavaScript, без сборщика). Логика разнесена по файлам следующим образом:

- **`index.html` — разметка и «экраны»**  
  - Общий каркас: шапка, навигация, подзаголовки под текущий режим.  
  - **Главная (`#/`):** блок подбора темы по запросу (роутер таксономии), запуск пайплайна с именем коллекции, список коллекций с переходом в коллекцию.  
  - **Экран коллекции (`#/collection/<id>`):** заголовок и метаданные коллекции, список статей, блок дайджеста (кнопка создания и вывод разделов), блок Q&A (поле вопроса и ответ с источниками).

- **`styles.css` — оформление (design layer)**  
  Сетка страницы, карточки, формы, кнопки, списки коллекций и статей, блоки результатов, индикаторы загрузки и ошибок, адаптив под узкие экраны.

- **`app.js` — логика и «сервисы» клиента**  
  - **Маршрутизация (hash‑router):** разбор `location.hash` (`/` и `/collection/:id`), переключение видимости экранов, загрузка данных при входе на маршрут.  
  - **Слой API:** функция `fetch` к REST backend (`/api/router`, `/api/pipeline/run`, `/api/collections`, Q&A, дайджест); разбор JSON и сообщений об ошибках.  
  - **Состояние:** идентификатор текущей коллекции, последняя выборка роутера для запуска пайплайна.  
  - **Отрисовка:** безопасный вывод в DOM (`escapeHtml`), карточки коллекций и статей, разбор и показ дайджеста по разделам, вывод ответа Q&A и списка источников.  
  - **UX:** блокировка кнопок на время запроса, спиннеры и текстовые статусы («Подбор темы…», ошибки сети).

В клиенте не используются сторонние JS‑фреймворки: только **Fetch API**, **DOM API** и шрифт **Manrope** (Google Fonts). Сборка не требуется — статика отдаётся FastAPI с префиксом `/static/`.

## Описание структуры серверной части

Серверная часть построена из нескольких логических слоёв (от HTTP до хранения данных):

- **Транспортный слой (HTTP API)** — приложение FastAPI (`src/api/app.py`): приём JSON‑запросов, валидация тел по схемам (`schemas.py`), раздача статики веб‑интерфейса, CORS, единообразные ответы и коды ошибок. Точки входа: здоровье сервиса, роутер темы, запуск пайплайна, список коллекций, Q&A по коллекции, генерация дайджеста.

- **Слой интеллектуальной маршрутизации (агенты)** — LangGraph‑роутер (`src/agents/router.py`): по тексту пользователя выбирает узлы таксономии D/GA/A или запрашивает уточнение; модуль Q&A (`qa_agent.py`) связывает запрос пользователя с RAG и LLM. Этот слой не заменяет пайплайн, а задаёт параметры темы и вызывает сценарии «ответ по коллекции».

- **Слой пайплайна сбора и подготовки контента (ingestion)** — последовательное выполнение этапов в `src/main.py`: сбор новых статей из RSS с учётом состояния лент, фильтрация по ключевым словам и эмбеддингам, извлечение полного текста, при необходимости суммаризация. Результат привязывается к записи коллекции в БД.

- **Слой индексации RAG** — модуль `rag_prep.py` и `chunking.py`: разбиение текстов на чанки, вычисление эмбеддингов, запись и обновление строк в `rag_documents` (pgvector) с привязкой к `collection_id`. Обеспечивает основу для поиска по смыслу внутри коллекции.

- **Слой поиска и ответа (Q&A)** — `src/qa/retrieval.py` (векторный поиск чанков), `rerank.py` (уточнение релевантности), `answer.py` (сборка контекста и вызов LLM). Используется при запросе «вопрос по коллекции» из API или агента.

- **Слой формирования дайджестов** — пакет `src/digest/`: загрузка чанков коллекции, кластеризация и описание тем, разнесение по разделам (тренды, методы, инструменты, кейсы), сборка итогового текста/структуры для выдачи клиенту.

- **Слой хранения и конфигурации** — `src/tools/db_state.py` (PostgreSQL: коллекции, RAG‑документы, обработанные статьи, состояние RSS), параметры окружения и поведения в `config/config.py`, таксономия и промпты в `data/`. Все верхние слои опираются на этот слой для персистентности и настроек.

## Описание структуры хранения данных

- **`processed_articles` (PostgreSQL)** — все увиденные статьи из RSS: источник, уникальный `link`, дата публикации, заголовок, краткое описание из ленты; дедуп по ссылке. Используется для выборки окна «последние N часов» в пайплайне.

- **`last_published_at` (PostgreSQL)** — по каждому ключу RSS‑источника хранится максимальная дата публикации среди обработанных записей; позволяет инкрементально подтягивать только новые публикации.

- **`collections` (PostgreSQL)** — логические коллекции знаний: имя, узлы таксономии (discipline, ga, activity), `collection_key`, при необходимости user/team, временные метки создания и последнего обновления.

- **`rag_documents` (PostgreSQL + pgvector)** — чанки для RAG: привязка к `collection_id`, `link` статьи, `chunk_index`, заголовок, summary, источник, дата публикации, `text_payload`, вектор `embedding`, служебные поля. Уникальность по `(collection_id, link, chunk_index)`; векторный поиск по коллекции.

- **`data/taxonomy.json`** — доменная таксономия D/GA/A, ключевые слова и описания топиков для фильтров и роутера (файловое хранилище, версионируется вместе с кодом).

- **`data/prompts.json` и `data/prompts/*.txt`** — шаблоны и фрагменты промптов для LLM (суммаризация, фильтры по заголовку/тексту).

- **`outputs/`** — выгрузки пайплайна (например, `articles_filtered.csv`) и вспомогательные артефакты тестов; не участвуют в онлайн‑Q&A, при необходимости очищаются вручную или политикой эксплуатации.

- **`config/config.py`** — не БД, но единый источник параметров подключения к PostgreSQL, имён таблиц, размерности эмбеддингов и прочих констант, влияющих на схему и объём хранения.

## Конфигурация

Основные параметры настраиваются в `config/config.py`:

- `RSS_FEEDS` - словарь RSS-лент для парсинга
- `TAXONOMY_SELECTION` - выбранные узлы таксономии (discipline, ga, activity) для фильтрации
- `DEFAULT_HOURS_BACK` - окно времени для сбора статей (по умолчанию 72 часа)
- `DEFAULT_EMBED_THRESHOLD` - порог для фильтрации по эмбеддингам
- `GIGACHAT_CREDENTIALS` - учетные данные для GigaChat API

## Технологии

- **Клиент:** HTML5, CSS3, нативный JavaScript (ES5/ES6), Fetch API; шрифт Manrope.
- **Python 3.10+**
- **pandas** - обработка данных
- **feedparser** - парсинг RSS
- **pymorphy3** - лемматизация русского текста
- **sentence-transformers** - генерация эмбеддингов
- **trafilatura** - извлечение текста из веб-страниц
- **gigachat** - LLM для суммаризации
